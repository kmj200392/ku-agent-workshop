연습과 최종의 이야기 계열은 겹치지 않는다. 전용 기억 유형 외에도 전체 평가가 여러 턴의 대화와 도구 결과 재사용을 요구한다. 각 문항의 모든 턴을 통과해야 1점을 얻으며, 동점은 공동 순위다.

기존 BFCL 26문항은 유지했다. 그중 최종 14개 변형의 불완전한 여권 표현, 모호한 날짜, 취소 후 청구서·승인·고객지원 지시를 명확히 했다. 기존 초기 상태와 참고 정답은 바꾸지 않았다. 추가 16문항은 원본 TravelAPI와 채점기로 새로 작성한 **수업용 문제**이며 공식 BFCL 신규 문제라고 부르지 않는다. 모든 변경 전후와 출처는 문항별 `provenance`에 있다.

생성: `python3 scripts/bfcl/expand-v2.py`. 기준 Git 스냅샷은 `f98b7b6`, 고정한 문제 파일 SHA-256은 `5319c1ef6d8f4b2604922b90033228254b7611b1f3e97c10cb6cf3bedf5458eb`이다. 원본 Python 도구·채점기 파일의 해시는 변하지 않았다. 세 에이전트를 실행하기 전에 문제와 코드를 고정했으며, 이번 점수에 맞춰 문항이나 코드를 다시 조정하지 않았다.

## 학생에게 보이는 연습 피드백

- 첫 실패 턴을 먼저 표시한다.
- 사용자 요청, 공개 참고 동작, 실제 도구의 인수와 반환 결과, 그 턴의 답변을 확인할 수 있다.
- 채점기의 오류 종류를 한국어로 설명한다. 예: 필요한 도구 실행 없음, 기다려야 할 턴에 실행, 작업 후 상태 불일치, 필요한 조회 결과 누락.
- 검사는 누적이므로 이후 실패를 별개의 새 오류로 단정하지 않는다. 기록이 생략된 경우도 실행하지 않았다는 뜻으로 해석하지 않는다.
- 참고 동작은 유일한 호출 문자열 정답이 아니다. 다른 흐름도 원본 상태·결과 검사를 만족하면 통과한다. ID·금액은 앞선 입력·관측에서 얻어야 한다.
- 추가 모델 호출 없이 브라우저에서 설명을 구성한다. 최종 결과에는 이 연습용 정답 비교 화면을 붙이지 않는다.

총 126문항 실행을 완료했고, 모델 요청 999개가 모두 HTTP 200이었다. 반환 모델은 모두 `gpt-6-luna`, reasoning token은 0이었다. API·런타임 오류로 중단된 사례는 없었다. 시간은 각 문항의 브라우저 실행·도구·채점을 포함한 합계이며, 학교 API 시간으로 환산하지 않는다.

테스트는 강사용 OpenAI `gpt-6-luna`, Chat Completions, `reasoning_effort=none`, 최대 출력 2,048토큰으로 진행했다. 학생용 학교 API 설정은 유지했다. 동일한 브라우저/Pyodide 실행기·채점기와 턴당 모델 8회/도구 16회, 문항당 모델 40회/도구 80회/180초 제한을 적용했다. 각 버전은 연습과 최종을 합친 동일한 42문항을 한 번씩 평가했다.

- **기억 제거:** 매 사용자 턴마다 대화를 초기화하는 대조군.
- **기본 코드:** 현재 배포하는 학생 시작 코드. 이 비교를 위해 성능을 낮추는 수정은 하지 않았다.
- **개선 코드:** 이전에 만든 강사용 코드. 전체 작업 계획을 검증하고, 필수 정보·도구를 확인하며, 앞선 결과와 상태를 재사용한다. 이번 실행을 위해 수정하지 않았다.

원시 기록은 키 없이 로컬 `outputs/benchmark-v2-luna-2026-10-29/`에 보관한다. 강사용 코드와 원시 기록은 배포에 포함하지 않는다. 집계·소스 해시·프로토콜은 [benchmark-v2-results.json](benchmark-v2-results.json), 문제 분포는 [benchmark-v2-manifest.json](benchmark-v2-manifest.json)에 있다. 로컬에서 `python3 scripts/bfcl/summarize-v2.py`로 완료 기록을 검증하고 집계를 재생성할 수 있다.

## 점수와 설계의 해석

기본 코드에서 개선 코드로 연습 5/12 → 11/12, 최종 11/30 → 26/30으로 높아졌다. 단순 문항 수 증가뿐 아니라 계획·입력 확인·기억을 구현했을 때의 차이를 관측했다. 기본 코드는 환전 결과를 예산에 반영하지 않거나 이미 제공된 토큰 대신 재인증을 시도하는 오류가 있었다. 개선 코드도 확장 예약 기록에서 조회만 반복하고 요청한 작업을 빠뜨리거나, 명시적인 취소 요청 전에 취소하거나, 자체 계획 해석기가 지원하지 않는 표현을 생성해 실패했다. 만점이 자동으로 나오도록 구성한 평가는 아니다.

처음에는 새 연습의 인증·카드 결과 재사용, 누락 정보 보완, 두 예약 구분부터 시작하고, 도구 부족 시 복합 요청 보류와 확장 기록 탐색으로 넘어가는 것이 좋다. 실패 한두 개를 빠른 테스트로 고친 뒤 전체 평가로 돌아오도록 안내한다.

다만 이는 세 구현을 각 한 번 실행한 수업용 검증이다. 40명의 점수 분포나 반복 실행 분산을 측정한 것은 아니다. 최종 30문항은 17개 이야기의 변형이라 통계적으로 독립인 30개 업무가 아니다. 기존 최종 20문항은 강사용 코드 개발 때 이미 검토했으므로 개선 코드의 성적은 독립 블라인드 평가 성적이 아니다. 추가 문항도 같은 개발자가 작성했다.

OpenAI에서 관측한 시간은 학교 API의 지연·호출 제한·40명 동시 접속을 보장하지 않는다. 20:35–20:55 최종 평가 시간은 유지하되, 학생에게 탭을 열어두고 개인 크레딧을 확인하도록 안내한다. 클라이언트 채점 구조의 결과는 학생 브라우저가 보고하는 점수이며 부정행위를 서버가 독립 검증하는 대회 시스템은 아니다.

## 기능·채점 검증

- Node 단위 검사 17개: 문항·분리·출처, 결과 업로드 필드, 모델 제공자, 코드 고정, 피드백의 첫 실패·누적 실패·기록 생략 등.
- Python 검사 12개: 42개 참고 정답 모두 통과, 아무것도 하지 않는 구현은 42개 모두 실패, 호출 보류 턴의 불필요한 조회는 실패, 잘못된 예약 대상은 실패, 신규 문항의 마지막 필수 행동 누락은 실패.
- 실제 Chrome/Pyodide에서 42개 참고 정답 모두 통과. 호출 한도 초과는 일반 실패로 처리하고 다음 문항을 이어간다.
- 선택한 1개·3개만 실행, 회원 등록 없이 빠른 테스트, 빠른 테스트 서버 업로드 없음, 공식 12문항 점수와 최종 후보 유지, 새로고침 시 결과 유지·API 키 삭제를 실제 브라우저에서 확인.
- 공식 평가에 3개만 제출하면 서버가 거절한다. 최종 30개 완료·고정 코드/모델·재시도·완료 점수 덮어쓰기 방지·마감 처리를 격리 데이터베이스로 확인.
- 학교/OpenAI 제공자, Python Worker, 강의 소개와 기존 시연 보존 회귀 검사 통과. 모바일 390px 가로 넘침 없음, 실제 실패 기록 표시와 최종 결과의 연습 해설 제외 확인.
- Next.js 프로덕션 빌드와 TypeScript 검사 통과. 검증용 참가자·점수는 운영 리더보드에 업로드하지 않았다.

v2의 점수와 최종 후보는 v1과 분리된다. 이전 6문항 점수만 있는 참가자는 마감 전에 새 전체 12문항 평가를 완료해야 한다. 기존 에이전트 편집 내용은 유지한다.
